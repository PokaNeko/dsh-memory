## 现状基线（2026-11-12 实测）

测量命令与读数都记在这里，便于下批复盘对比。

| 项 | 读数 | 测法 |
|---|---|---|
| 版本 | 发布仓 `0.6.1`；本机工作副本 `0.6.0`（`profiles/plugins/dsh-memory`） | 各自 `package.json` |
| 代码量 | `index.js` 55,187 B ／ `client.js` 37,445 B ／ `lib/` 14 个模块合计约 2,150 行 | `Get-ChildItem` + 行数统计 |
| 测试 | **smoke 49 / 49**、**client-smoke 9 / 9** 通过；`apply-stub` 未跑通（需同级 `dsh-api-stable`，属环境前提非代码缺陷） | `node test/smoke.test.mjs`、`node test/client-smoke.test.mjs`（**直接跑文件**；`node --test` 在受限沙箱里 spawn 会 EPERM） |
| 卡片数 | 340 张 | `data/cards.json` → `cards.length` |
| 增速 | 约 **20 张/天**（近 12 天 256 张） | 按 `createdAt` 分组 |
| cards.json | **7.34 MB** | 文件字节数 |
| 卡片正文合计 | **30,468 字符**（约 30 KB） | `Σ content.length` |
| 单卡 embedding | 1024 维，存于卡片内 | `cards[0].embedding.length` |
| 文件体积构成 | **约 99.6% 是 embedding** | 7.34 MB vs 30 KB |
| `data/` 总量 | 51.3 MB，其中 `backup/` 约 42 MB | 目录递归求和 |
| 写入落盘 | 每次整库 `JSON.stringify(…, null, 2)` + `tmp → rename` | `lib/store.js#save` |
| `save()` 调用点 | `engine.js` 86/249/306/350、`ingest.js` 322、`maintenance.js` 96/178 | grep |

基线里最重要的一条不是数字，是比例：**7.34 MB 里只有 30 KB 是「记忆本身」**，其余是可由 `bge-m3` 从正文重算的派生向量。这条决定了 B 组（真源与派生分离）的优先级——见清单。

## 维护约定

1. 改代码前先确认改动落在哪条不变量上（契约 §4）；落不上就先讨论，不要直接写。
2. 每批改动只做一组（A/B/C/D），**不混批**。混批的验收无法归因，回滚无法定点。
3. 读数变了就更新上表，并在清单里记一笔「复测日期 + 前后值」。
