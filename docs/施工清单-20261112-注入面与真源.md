# 施工清单 · 2026-11-12 · 注入面与真源

> 依据：[注入面契约.md](注入面契约.md) 的 I1–I7。
> 参照对象：灵枢（FuRongJun-1999/dsh-memory）的工程纪律——**不是搬架构**，只借四条已被它踩实的教训。
> 本文只列「要改什么、怎么验收、怎么回滚」。不写实现细节，实现时另开分支。

## 0. 借什么、不借什么

| 借 | 不借（明确排除） |
|---|---|
| 「只改写注入副本，真源保真」 | 两段式提交 / WAL / 双实例互验 |
| 「原文即真源，索引只是派生物」 | 蜂群运行时、中文编译器、元认知单元 |
| 「绝不假装成功，成功要有判据」 | 30 个工具面、角色扮演网页、图形界面增量包 |
| 「每条决策留根因与伤害路径」 | 整目录耦合（71.9 MB 资产同树分发） |

排除理由统一一句：**它们解决的是「多进程并发写同一个库」，我们是单机单进程、日均 20 张卡**。引入只会增加故障面，不增加能力。

## A 组 · 注入面（P0，先做）

**为什么排第一**：这一组挡的是「会话永久不可用」，是唯一**用户自己修不了**（需要先删卡才能恢复）的故障类。改动量小、完全隔离、可测。

### A1 · hot 块 `{{` 打断

- **现状证据**：`index.js` 约 696–704 把 `hotTextFor()` 的返回值注册为 `systemPrompt.context` 文本；宿主 `dsh-system-prompt/lib/index.js:147` 对每个 context 调 `interpolate()`，遇完整 `{{…}}` 组抛错（`:158/:164/:167/:170`），且宿主明确**无转义语法**（`README.zh.md:173`）。
- **实测风险**：当前 340 张卡中，含**完整** `{{group}}` 的 0 张；含**裸** `{{` 的 1 张（缺配对右括号，属普通文本）。即：目前安全，但只差一个字符。
- **改法**：在**出口**加 `escapePromptBraces()`——逐对打断相邻 `{`（`{{` → `{ {`），不动真源、不动工具返回。注入路径唯一入口统一调用，禁止各调用点各写一份。
- **验收**：`test/injection-surface.test.mjs` ① 含 `{{name}}` 的卡渲染后不含 `{{`；③ 渲染前后 `store` 内原文深度相等。
- **风险**：低。纯函数、无 I/O、无状态。
- **回滚**：删除该调用点即回到旧行为（旧行为在无 `{{` 卡时与新版逐字节相同）。

### A2 · 不可信记忆边界

- **现状证据**：召回通知 `memoryNotice()`（`index.js:1045`）只用 `[memory recall]` / `[/memory recall]` 文本围栏 + 一句「仅供参考」；hot 块（系统提示内）**无任何边界或声明**。仓内 `untrusted` 关键字 0 命中。
- **改法**：统一渲染函数，顺序固定：**声明句（边界外）→ 开界标记 → 载荷 → 闭界标记**；载荷内出现的边界标记形态先打断。变体至少覆盖：半角/全角斜杠、零宽字符、带属性、HTML 实体。
- **验收**：④ 注入块中边界标记形态**恰为 2 处**；⑤ 载荷自带闭合标记时仍恰为 2 处；⑥ 声明句位于开界标记之前。
- **风险**：中低。会改变模型看到的形态，极少数依赖旧围栏文本做判断的逻辑（历史查重按「围栏块全文相等」判定，见 `index.js:665`）**需要同步改判据**，否则查重失效 → 重复注入。
- **回滚**：边界由单点常量开启/关闭；关闭后输出与旧版逐字节一致（需测试钉住）。

### A3 · 出口卫生（孤立代理 + 长度预算）

- **现状证据**：注入路径不对卡片正文截断（`renderHotBlock` 按整卡装预算、不切内容），因此当前**无实际触发点**；但 `/memory` 命令面与 IM 路径存在多处 `slice(0, n)`。
- **改法**：提供 `truncateSafe()`（不劈开代理对、出口清孤立代理），先只用在确有截断的位置，不盲目铺开。
- **验收**：② 含孤立代理的文本经出口处理后无落单码元；幂等（重复处理结果不变）。
- **风险**：低。
- **说明**：这一项**不是当前事故**，属于「顺手补上，防未来加截断时踩坑」。不要为了它推迟 A1/A2。

### A4 · 全路径审计

- **要求**：把「记忆文本 → 模型可见」的所有路径列全（`systemPrompt.context`、`agent/pre-step` 通知、`/memory` 命令输出、IM 攒批提示词、导出文件），逐条标注「是否过净化」。输出一张表附在本清单末尾。
- **验收**：表里没有「未知/待查」项。
- **风险**：无（只读排查）。

### A5 · 守卫测试落位

- **要求**：A1–A3 的断言写进 `test/injection-surface.test.mjs`，命名按断言做的事，不复用编号。
- **验收**：`node test/injection-surface.test.mjs` 全绿；**故意把 `escapePromptBraces` 改成直通**时测试必红（负向对照能做出来，才算真守卫）。
- **风险**：无。

## B 组 · 真源与派生分离（P1，单独一批）

**为什么排第二但单独一批**：它要动 `store.js` 与一次数据迁移，是本清单里**唯一会碰已有数据**的改动。与 A 组合批会让「会话坏了」和「数据坏了」两种故障无法归因。

### B1 · embedding 移出 `cards.json`

- **现状证据**：`cards.json` 7.34 MB；卡片正文合计 30,468 字符（约 30 KB）；每卡 1024 维向量 → **约 99.6% 体积是派生数据**。
- **改法**：`cards.json` 只留原文与元数据；向量写入独立派生文件（建议定长二进制 `Float32`，按 `id` 索引）。`store.load()` 时合并，向量缺失视为「待重建」而非错误。
- **收益**（按 20 张/天估算）：3 个月约 2,000 张时，单文件从约 43 MB 降到约 200 KB；派生文件约 8 MB；每次写入的整库回写代价同步下降。
- **验收**：`test/truth-derived.test.mjs` ①②③；另测「cards.json 可被 diff 阅读」。
- **风险**：中。需一次性迁移 + 回读校验；迁移失败必须保留原文件不覆盖。
- **回滚**：保留迁移前的 `cards.json` 副本（一次性、命名带日期），失败即还原。

### B2 · 写入路径去掉整库美化输出

- **现状证据**：`store.save()` 用 `JSON.stringify(payload, null, 2)`；调用点 7 处（`engine.js` 86/249/306/350、`ingest.js` 322、`maintenance.js` 96/178）。
- **改法**：B1 落地后 `cards.json` 已足够小，indent 可保留（有利于 diff）。**若不做 B1，则此项优先级降为 D 组**——单独去掉 indent 只是把 7 MB 变 4 MB，治不了根。
- **风险**：低。
- **注**：不要把 B2 当成 B1 的替代。

### B3 · 备份策略

- **现状证据**：`data/backup/` 约 42 MB（5 份 auto-* 各 5–7 MB + 历史手动备份），是全库体积的主要占用者。
- **改法**：B1 后备份自然变小；再把 auto 保留份数从 5 降到 2–3 份，并明确「手动备份永不自动删」这条边界不变。
- **验收**：备份目录体积下降且至少保留一份可恢复快照。
- **风险**：低，但**属删数据类操作**——按约定必须先列清单、经确认后才动。

### B4 · 迁移与重建脚本

- **要求**：一次性脚本：迁移 → 校验（卡片数、抽样向量余弦误差）→ 重建派生 → 对比 recall 结果；每一步失败即停并保留现场。
- **验收**：在副本上跑通三次（幂等），再对真库执行一次。
- **风险**：中。

## C 组 · 写入语义（P1，改动小，可排在 A 之后）

### C1 · 写入成功判据

- **现状证据**：`store.save()` 为 `tmp → rename` 原子写，但**不校验读回**；`ingest`/`maintenance` 的失败处理以日志为主。
- **改法**：落盘后读回校验（长度 + 关键字段），失败进重试队列并带可读原因。
- **验收**：`test/write-semantics.test.mjs` ①②（注入抛错 → 断言可判别失败 + 队列有条目 + 有原因日志）。
- **风险**：中。碰主写入链，需先把 A 组的守卫跑绿再动。

### C2 · embedding 缺失时的幂等缺口

- **现状证据**：ADD 去重判据是 `cosine ≥ 0.92` **或** `sameFactNormalized`（`ingest.js:249–268`）。`cosine()` 对非数组入参安全返回 0，因此 embedding 为 `null` 时**不崩**，但只剩字面归一化一条腿——措辞微变即可能新增重复卡。
- **改法**：为「向量缺失」的卡补一条重建队列；或在 ADD 判据里对 `vec == null` 走更严格的字面等价判定。
- **验收**：③ 同批对话跑两遍卡片数不变；④ embedding 返回 `null` 时重跑仍不新增（修复前允许标 `todo`）。
- **风险**：低。

### C3 · 失败可见性

- **要求**：写入失败至少出现在一处用户可见面（`/memory` 状态或设置页），不能只留在 `debug.log`。
- **风险**：低。

## D 组 · 工程纪律（P2，持续）

| 项 | 内容 | 验收 |
|---|---|---|
| D1 | 守卫测试与不变量一一对应（契约 §5 矩阵） | 矩阵里每行都有可实现文件 |
| D2 | CHANGELOG + 版本协议：破坏性改动（如卡片字段变更、命令改名）必须单列并给迁移步骤 | 存在 CHANGELOG 且最新版本条目完整 |
| D3 | 注释约定：**根因 / 伤害路径 / 为什么不是那样做** 三段式（只在非显然处用，不铺满） | 抽查 5 处新增注释符合 |
| D4 | 基线表随改动更新（`docs/README.md`） | 每次动数据/测试后有一行更新 |

## 执行顺序与批次边界

```
A1 → A2 →（A3 顺手）→ A4 审计 → A5 测试   ← 一批，只碰注入路径
        ↓ 验收：49 + 新增测试全绿
C1 → C2 → C3                              ← 第二批，只碰写入路径
        ↓ 验收：写失败可见、重跑不重复
B4 → B1 → B3 →（B2 视情况）                ← 第三批，碰数据，单独排期
        ↓ 验收：派生可重建、recall 逐位一致
D1–D4                                      ← 持续
```

**硬规矩**：一批只做一组；验收不全绿不进下一批。

## 范围守卫（本清单明确不做）

- 不引入 SQLite / 向量库 / 外部服务（单机单进程，现规模不值得）。
- 不新增默认暴露的工具或命令。
- 不改 `client.js` 的 UI 结构（它不在注入面上）。
- 不搬灵枢的并发/一致性机制。
- 不在本清单内删任何数据（B3 的删除动作按约定另行列清单确认）。

## 待裁决（需要人定，不要自己决定）

1. **B 组时机**：数据现在只 7.34 MB，可以拖；但越晚迁移，迁移时要校验的卡越多。建议在卡片数破 1,000 前做完。
2. **备份保留**：auto 保留 2 份还是 3 份；历史手动备份（10 月那批）是否归档到别处而非留在 data/。
3. **C2 严格度**：向量缺失时是「宁可重复一张」还是「宁可漏记一条」——这是产品取向，不是技术选择。
