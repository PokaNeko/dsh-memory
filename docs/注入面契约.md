# 注入面契约（Injection Surface Contract）

> 适用范围：`index.js`、`lib/tiers.js`、`lib/store.js`、`lib/models.js`、`lib/ingest.js` 中**任何会把记忆文本送进模型上下文**的代码路径。
> 定位：本文规定「不许破坏什么」。功能设计不在本文范围。

---

## 0. 这份文档要解决什么

dsh-memory 的核心动作只有两个：**把对话写成卡片**、**把卡片读进提示词**。前者错了，记忆脏；后者错了，**整个会话不可用**。

后者之所以危险，是因为记忆正文来自用户输入、助手输出、工具结果、群聊消息——**内容完全不可控**。不可控的文本一旦被塞进宿主提示词，就可能同时触发三类事故：

1. **渲染事故**：宿主模板语法把正文里的字符当成变量引用，抛错，会话死。
2. **注入事故**：正文里的「忽略以上指令」被模型当成指令执行。
3. **编码事故**：截断/拼接产生非法 Unicode 码元，服务端拒整条请求。

三类事故的共同点：**只坏在出口，不坏在入口**，而且**每轮重放**——一次污染就让该会话永久不可用（历史只增不改）。所以治理点必须放在**注入边界**，而不是写入侧。

## 1. 三个名词

| 名词 | 指什么 | 谁可以改 |
|---|---|---|
| **真源** | `data/cards.json` 里的卡片正文与元数据 | 只能由业务逻辑改（ingest / maintenance / gc / 手动命令）。**净化函数一律不得触碰** |
| **派生** | 可由真源重算的东西：embedding、BM25 索引、热块文本、召回候选 | 可随时丢弃重建。丢了的正确行为是重建，不是报错 |
| **注入副本** | 每一轮为拼提示词临时生成的字符串 | 可以任意改写。**所有转义/打断/截断只允许发生在这一层** |

**判据**：如果一个函数会同时出现在「写进 cards.json」和「拼进提示词」两条路径上，它就不该做任何改写型处理。改写只属于注入副本。

## 2. 宿主事实（不是我们的选择，是必须适配的环境）

来自 `@deepseek-ai/dsh-system-prompt`，本地版本随宿主安装：

| 事实 | 证据 |
|---|---|
| 每个 `systemPrompt.context` 文本都会被 `interpolate()` 处理 | `lib/index.js:147` → `text: interpolate(context, assembly.variables, "context")` |
| 插值以 `text.indexOf("{{")` 为扫描锚点 | `lib/index.js:155` |
| `{{` 之后若存在 `}}` 但不成简单组 → **throw** | `lib/index.js:158` |
| 组成立但变量名不合法 → **throw** | `lib/index.js:164` |
| 变量名合法但未注册 → **throw** | `lib/index.js:167` |
| 已注册但值为 `undefined` → **throw** | `lib/index.js:170` |
| **没有字面量 `{{…}}` 的转义语法** | `README.zh.md:173` |
| 只有孤立的 `{{`（无后续 `}}`）被视为普通文本 | `lib/index.js:106` 注释 + `:158` 的条件 |

推论（已核对，非推测）：**卡片正文里只要出现一个完整的 `{{xxx}}` 组，就会让当轮 `system-prompt/assemble` 抛错。** 而热块每轮重建 → 同一张卡在库里，该会话就每轮失败。这不是偶发故障，是持久故障。

## 3. 当前的两个注入面

| # | 面 | 机制 | 文本来源 | 现有防护 |
|---|---|---|---|---|
| ① | **hot 块**（进系统提示） | `index.js` 约 696–704 注册 `systemPrompt.context({ name:'dsh-memory:hot', order:1000, text: hotTextFor })` | `lib/tiers.js#renderHotBlock` ← `store.hot()` 的卡片正文 | **无** |
| ② | **召回通知**（进对话） | `agent/pre-step` → `memoryNotice(hits)`（`index.js:1045`）→ `createUserMessage({ source:{ kind:'plugin:dsh-memory' } })` | 卡片正文 + 元数据 | 只有 `[memory recall]` / `[/memory recall]` 文本围栏 + 一句「仅供参考」 |

补充事实：

- ② 走的是**用户消息**通道，不经过 `interpolate` → **`{{` 对 ② 无风险**，但对 ① 是致命风险。两者不能套用同一套结论。
- ② 的围栏是**给模型看的文本**，不是解析器认的标签：载荷里若自带 `[/memory recall]`，模型看到的是一个提前闭合的块。这与 ① 的 `{{` 属不同缺陷类，但同属「注入副本未净化」。

## 4. 不变量（I1–I7）

> 每条格式：**要求 / 为什么 / 判定 / 破了会怎样**。
> 「判定」一栏写的是可执行检查，不是态度。

### I1 · 注入副本必须净化

- **要求**：任何进入 prompt 的文本，出口前必须过同一个净化函数，至少做两件事：**打断 `{{`**、**清除孤立代理对**。真源逐字节不动。
- **为什么**：见 §2 的宿主事实；孤立代理对经 `JSON.stringify` 变成 `"\ud83d"`（合法 JSON、非法码元），严格校验的服务端会拒掉整条请求。
- **判定**：`test/injection-surface.test.mjs` ① 给含完整 `{{x}}` 的卡，断言渲染结果里**不含** `{{`；② 给含孤立代理的文本，断言输出无 `[\uD800-\uDFFF]` 落单码元；③ 断言 `store` 里的原文**未被改动**。
- **破了**：① 该会话每轮请求失败，只能靠改/删卡恢复；② 该会话历史被写入非法码元，**不可逆**。

### I2 · 记忆正文是不可信数据，必须带边界与声明

- **要求**：记忆正文进入 prompt 时必须被显式边界包裹，且声明句写在边界**之外**；载荷里出现的边界标记形态必须先被打断（含全角/零宽/带属性/HTML 实体等变体）。
- **为什么**：卡片正文可沉淀任意用户输入与工具输出。没有边界时，模型无法区分「数据」与「指令」，这是提示注入面的标准形态。
- **判定**：`test/injection-surface.test.mjs` ④ 断言注入块中边界标记形态**恰为 2 处**（真开 + 真闭）；⑤ 载荷自带 `</untrusted-memory>` 时断言注入块仍恰为 2 处且全角/零宽变体被打断；⑥ 断言声明句位于开界标记**之前**。
- **破了**：一条被污染的记忆可以在后续所有会话里伪造指令。

### I3 · 净化只作用于注入副本

- **要求**：I1/I2 的改写不得回写 `cards.json`；`cg`/`recall` 等工具面返回的正文必须是原文。
- **为什么**：记忆系统的价值在保真。写入侧转义会不可逆失真，且检索、导出、回放全部被污染。
- **判定**：`test/injection-surface.test.mjs` ③（改前后 `store.all()` 深度相等）+ ⑦ 断言 `/memory recall` 输出中的正文与 `cards.json` 逐字节一致。
- **破了**：一旦失真就无法只靠「关掉开关」回滚——伤的是数据本身。

### I4 · 真源与派生分离

- **要求**：`cards.json` 只存正文与元数据；embedding 属派生，必须可重建。删除派生存储后，系统应能重建并恢复检索，而不是报错或降级成永久字面检索。
- **为什么**：当前 7.34 MB 中 99.6% 是 embedding（正文合计 30 KB）。派生与真源混存导致三个后果：整库回写代价随卡片数线性增长、备份体积放大、diff/review 不可读。
- **判定**：`test/truth-derived.test.mjs` ① 删派生文件后 `init()` 能重建且 `recall` 结果与删除前**逐位一致**；② 断言 `cards.json` 里不含 `embedding` 字段；③ 断言重建是**幂等**的（连续两次重建结果相同）。
- **破了**：真源不可读、不可 diff；迁移与排障成本持续上升；备份策略被向量体积绑架。

### I5 · 写入成功必须有判据，失败必须可见

- **要求**：只有「已落盘且可读回」才算成功；失败必须至少出现在一处可见面（返回体 / 日志 / 重试队列），不得静默吞掉。
- **为什么**：`tmp → rename` 能防半截文件，但防不了「写完了但调用方不知道」。若失败被吞，用户会以为记住了——这比记住失败更糟。
- **判定**：`test/write-semantics.test.mjs` ① 注入 `save()` 抛错，断言调用方拿到可判别的失败信号且重试队列有条目；② 断言失败路径写了一条带原因的可读日志。
- **破了**：记忆静默丢失，且事后无法区分「没记」与「记了没读到」。

### I6 · 重试必须幂等

- **要求**：同一内容的重试不得新增第二张卡（同内容指纹 → 复用既有卡）。
- **现状（已核实，勿误判为缺陷）**：ADD 阶段已有确定性去重兜底——`cosine ≥ dupThreshold(0.92)` 或 `sameFactNormalized` 命中即 `continue`（见 `lib/ingest.js:249–268`）。**但该判据依赖 embedding 可用**；embedding 为空时只剩字面归一化这一条腿。
- **判定**：`test/write-semantics.test.mjs` ③ 同一批对话跑两遍，断言卡片总数不变；④ 在 embedding 返回 `null` 的情况下重跑，断言仍不新增（此为**已知缺口**，修复前该断言允许 `todo` 标记，修复后转硬断言）。
- **破了**：超时重试放大卡片数，去重阈值失效时更明显。

### I7 · 变更协议

- **要求**：任何可能触及 I1–I6 的改动，**同一批次**内必须带上对应守卫测试；守卫变红时不得通过修改断言放行，除非在 CHANGELOG/裁决记录里写明理由与裁决人。
- **为什么**：这类缺陷的共同特征是「本地手测发现不了、线上表现为会话死」。唯一可持续的防线是守卫测试，而守卫一旦可以被随手放宽，就等于没有。
- **判定**：人工检查 PR/提交是否同时包含代码与测试；测试文件的历史里是否存在「为放行而放宽断言」的提交。

## 6. 变更协议（操作细则）

1. **先定位不变量**：说清本次改动落在 I1–I6哪一条。落不上 → 先讨论需求，不写代码。
2. **同批带测试**：代码与守卫同一个提交。禁止「先上代码，测试下批补」。
3. **红了不改断言**：守卫红了先判断是「实现退步」还是「契约该改」。属后者时，**先改本文契约并记录理由**，再动断言。
4. **不混批**：一次只做清单里的一组（A/B/C/D）。
5. **读数留痕**：影响基线的改动（卡片数、文件体积、测试数）要在 `docs/README.md` 基线表里更新或追加一行。

---

## 7. 已知未覆盖面（诚实清单）

- ② 号注入面（召回通知）目前走用户消息通道，`{{` 风险为 0，但**提示注入面未治理**——本轮只解决「模型能看到边界」，不解决「模型一定遵守边界」。提示注入没有终局解，本契约只承诺降低成功率与提供可审计形态。
- `roleplay`/群聊等 IM 路径的文本进入系统提示前是否另有拼接点，本契约尚未覆盖，需在 A 组施工时补一次全路径审计。
- 零宽字符的**词内**插入（如 `untr\u200busted`）在打断逻辑里仍是已知残留，属可接受风险（需同时满足「模型认作标签」与「解析器认作标签」才会生效）。
